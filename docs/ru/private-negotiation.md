# Модель приватных переговоров

Переговоры работают как локальное вычисление, а не как публикация расписаний.
Каждый участник оценивает одинаковые явные варианты по своим локальным
ограничениям. В wire попадает только минимальный результат стратегии.

Alice может предложить Bob и Charlie `fri-18` и `sat-18`. Bob проверяет своё
локальное расписание и возвращает только `{ available: true, selected: [sat-18] }`.
Alice получает подписанный boolean/score, но не расписание Bob. Участник может
сделать abstain или reject без объяснения приватной причины.

`EXACT` используется только для намеренно опубликованного значения. Для
availability и предпочтений подходят `RANGE`, `BOOLEAN`, `SCORE` и
`REDACTED`; уровень по умолчанию — `REDACTED`. Core отклоняет `PRIVATE` и
`SECRET` в ответе, слишком большие производные значения, неизвестные option
IDs, плохие подписи, просроченные payload и повторные голоса.

При `ASK_EVERY_TIME` входящая сессия остаётся `pending` до
`approveSession`/`rejectSession`. Safe policy принимает известные контакты,
`DENY` отклоняет сессию до сохранения. Участник может выйти, host — отменить
или завершить; `sweep()` помечает expiry и не выбирает вариант молча.

Audit хранит только negotiation ID, peer, strategy, counts, status и
disclosure. Расписания, Memory, файлы, сообщения и tool results в него не
записываются. Ссылка на Agent Room не расширяет область данных.
