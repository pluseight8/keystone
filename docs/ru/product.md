# Продукт Keystone

Keystone — это ваш личный интернет: локальная платформа для идентичности,
данных, социального взаимодействия и персонального ИИ. Она объединяет то,
что вы делаете, знаете, создаёте и чем делитесь, не передавая вашу жизнь
обязательному облаку Keystone.

Вам не нужно переносить жизнь в Keystone. Keystone формируется вокруг вашей
жизни. Локальная работа продолжается без Интернета; внешние провайдеры
используются только там, где они действительно нужны.

## Один продукт, много поверхностей

Keystone строится вокруг канонических объектов и действий, а не вокруг
разрозненных мини-приложений. Один и тот же File, Task, Document, Contact,
Place, Message или объект публикации можно открыть из Search, Daily Layer,
рабочего пространства, другого устройства или явного сценария обмена.
Проекция показывает объект, но не создаёт второе хранилище или новый источник
полномочий.

| Область | Для чего она нужна |
| --- | --- |
| Главная / Daily Layer | Короткий необязательный обзор изменений и продолжения работы. |
| Messages и Calls | Приватные сообщения и голосовые/видеозвонки между разрешёнными идентичностями. |
| Mail | Локальная проекция и отправка через почтовый ящик владельца. |
| Люди / Contacts | Адресная книга владельца, отдельная от Identity и доверия Keystone. |
| Calendar | Запланированное или зарезервированное время. |
| Tasks | То, что нужно сделать. |
| Workboards | Организация проектной работы: списки, карточки и совместная работа. |
| Universal Inbox | Локальная поверхность внимания и действий из нескольких источников. |
| Files / Shared Folders | Основное файловое хранилище и явная авторизация общей синхронизации. |
| Vault | Персональные знания и заметки в формате Markdown. |
| Documents | Reader, OCR и аннотации поверх ревизий Files. |
| Photos | Личная медиатека изображений/видео и производных превью. |
| Browser / Web Library | Просмотр и явно сохранённые статические архивы Web. |
| Subscriptions / Podcasts | Выбранные владельцем внешние ленты и явно скачанные медиа. |
| Maps | Places, офлайн-карты и вручную запущенная географическая навигация. |
| Personal Web / Spaces | Явно опубликованные материалы и общие контексты. |
| Capture | Быстрый приём материала с последующим выбором назначения. |
| Search | Локальная навигация по разрешённым объектам. |
| Agents, Skills и Memory | Необязательная помощь, декларативные процедуры и явно управляемый контекст. |
| Devices, Continuity и Nearby Exchange | Перенос ссылок или копий между устройствами и ближайшими точками. |

Контракт конкретной области описан на её странице; [Архитектура](architecture.md)
объясняет, как поверхности соединяются.

## Модель продукта

Естественный поток выглядит так:

```text
захватить → поработать с данными → организовать → найти → использовать на устройствах
          → при необходимости поделиться/поработать вместе → при необходимости включить локальный ИИ
```

Например, короткая мысль может остаться в [Capture](capture.md), стать
[Task](tasks.md), получить время в [Calendar](calendar.md), ссылаться на
[File](files.md), читаться как [Document](documents.md), сохраниться заметкой
в [Vault](vaults.md) и снова найтись через [Search](search.md). Это связанные
варианты работы, а не конкурирующие базы.

## Польза для одного человека

Keystone полезен ещё до подключения других людей. Один владелец может
использовать персональный ИИ, Memory, Vault, Browser, Web Library, Capture,
Calendar, Tasks, Workboards, Files, Documents, Photos, Contacts, Mail,
Subscriptions, Maps и Search локально или с выбранными внешними источниками.
Shared Folders помогают синхронизировать собственные устройства без
превращения продукта в hosted-диск.

Agents, Skills, Automation и Continuity остаются полезными личными
инструментами. Локальный ИИ необязателен: основные сценарии имеют
детерминированные и обычные локальные пути.

## Работа с людьми и устройствами

Дополнительная ценность появляется, когда владелец явно подключает другую
Identity или доверенное устройство:

- Messages и Calls обеспечивают приватное общение между разрешёнными
  Keystone-идентичностями.
- Shared Folders и Spaces раскрывают только выбранные объекты и права;
  совместная работа не требует центрального регистратора социальной сети.
- Nearby Exchange отправляет проверенную копию или ссылку анонимной ближайшей
  точке. Получение не делает отправителя Contact, соавтором или доверенным
  устройством.
- Continuity передаёт ограниченную ссылку и контекст продолжения уже
  доверенному устройству, а не полную копию состояния компьютера.
- Personal Agents взаимодействуют через явные ограниченные запросы. Contact,
  ретранслятор, Profile или ближайшая точка не становятся Agent или источником
  полномочий автоматически.

Социальная сеть усиливает продукт, но не является условием начала работы.

## Границы похожих сущностей

### Files, Documents, Photos, Web Library и Capture

- **Files** — каноническая модель файлов и их ревизий.
- **Shared Folders** добавляют членство, авторизацию и распределённую
  синхронизацию вокруг Files; участник общей папки не является собственным
  устройством.
- **Documents** — Reader/OCR/аннотации поверх ревизий File. Reader и аннотация
  не переписывают исходный File.
- **Photos** — приватный индекс медиа. Оригинал остаётся оригиналом, а миниатюра,
  кадр и результат редактирования являются производными.
- **Web Library** хранит выбранную закладку или статический архив Web; архив
  не является живой страницей и не выполняет её скрипты и tracking.
- **Capture** — приём материала. Он принимает явный объект, показывает
  предложение назначения и маршрутизирует его только после подтверждения. Это
  не второй Inbox, Files, Vault или Web Library.

Подробности: [Files](files.md), [Documents](documents.md), [Photos](photos.md),
[Web Library](web-library.md) и [Capture](capture.md).

### Tasks, Workboards, Calendar и Automation

| Поверхность | На какой вопрос отвечает |
| --- | --- |
| Tasks | Что мне нужно сделать? |
| Workboards | Как организована работа над проектом? |
| Calendar | Когда время запланировано или зарезервировано? |
| Reminders | Когда напомнить о задаче? |
| Automation / Chronos | Когда должно произойти одобренное автоматическое действие? |

Напоминание — это уведомление, а не выполнение задачи. Текст Task — данные;
он не становится автоматизацией только потому, что его прочитал Agent или
модель.

### Contacts, Identity и Profile

Contact — приватная запись для организации людей и разрешения выбранных
адресов. Keystone Identity — криптографический субъект. Profile — вид
Identity, которым можно поделиться. Email, номер телефона, отображаемое имя,
членство в группе и данные Profile не являются авторизацией.

Связь Contact с Identity создаётся явно и может быть проверена. Contacts не
выводят отношения, не создают доверие, не распознают лица и не разрешают
сообщение, папку, Space или устройство.

### Разные виды входящих

- **Universal Inbox** — внимание и действия из разных источников.
- **Task Inbox** — стандартный список неклассифицированных Tasks.
- **Capture Tray** — необработанный ввод владельца.
- **Mail Inbox** — папка внешнего почтового ящика.

Они могут ссылаться друг на друга, но источник остаётся главным. Чтение
Universal Inbox не является отметкой прочтения Mail или выполнением Task.

## Главная и запуск

Владелец выбирает стартовую поверхность: последнее открытое место, Home,
Feed, Video, Messages, Vault, Maps, Mail, Photos, Tasks или другое доступное
рабочее пространство. Последнее открытое восстанавливает точный контекст с
повторной проверкой прав. Home не является обязательной.

Необязательный Daily Layer может находиться над выбранной поверхностью и
показывать изменения из Calendar, Tasks, Workboards, Messages, Spaces, Files,
Devices, Agents, approvals, Mail и других явно включённых источников. Он
хранит ссылки и состояние отображения, а не копию исходных данных. Если
ничего не требует внимания, тишина — корректный результат. Слой не считает
оценки продуктивности, здоровья, вовлечённости или местоположения.

## ИИ и полномочия

Keystone полноценно работает без генеративного локального ИИ. Совместимая
локальная модель необязательна, но рекомендуется для расширенной помощи.
Модель может быть встроенной или предоставленной llama.cpp, Ollama, LM Studio,
локальным OpenAI-compatible сервером либо собственной локальной средой.
Совместимость не означает доверие: модель всегда является недоверенным
вычислением.

Модели предлагают. Политика решает. Пользователь разрешает последствия.
Страницы Web, Mail, Messages, Documents, OCR-текст, элементы лент, имена
файлов и captured content — данные, а не инструкции и не полномочия. External
AI не получает Vault, Memory, Contacts, Mail, Tasks, Documents, Capture,
Location или приватные Files без явного действия.

## Сеть и внешние провайдеры

[Сеть Keystone](connectivity.md) — общая сеть продукта. Она может использовать
локальные, ближайшие, прямые, отложенные или провайдерские пути, но приложения
не зависят от выбранного транспорта. Интернет помогает Keystone, но Keystone
не зависит от Интернета.

External Mail, RSS/Atom/JSON Feed, Web и медиа-провайдеры сохраняют собственные
границы и полномочия. Keystone не является HTTP-прокси, центральным почтовым
сервером, облачным диском, сервисом рекомендаций, платёжным реестром или
системой аналитики. Внешние интеграции узкие и явные.

## Безопасность и приватность

Каждый источник обрабатывается согласно его полномочиям и классу данных.
Импортированный контент ограничен и недоверен. Обмен, публикация, раскрытие
провайдеру, размещение на устройстве, связывание Contact, использование
External AI и выполнение Tool — отдельные решения владельца. Хеш контента
проверяет целостность, но не выдаёт доступ. Путь указывает расположение, но
не даёт полномочий. Ретранслятор даёт доступность, но не становится
соавтором.

[Безопасность](security.md) — каноническая модель защиты, а [Релиз и
доказательства](release.md) фиксирует, что реально проверено на каждой
платформе.

## Первый запуск и ссылки в Desktop

Desktop начинает работу с короткой локальной настройки. Она создаёт настоящую
owner identity через identity service, подготавливает текущее устройство и
сохраняет профиль только после открытия долговечных локальных store. Здесь же
можно выбрать интересы, приватность, внешний вид, необязательный локальный ИИ
и явно выбранные файлы. При ошибке инициализации pending-профиль, marker и
owner-scoped store откатываются вместе; следующий запуск снова открывает
настройку.

После входа Home, Search, Activity Bar и вкладки работают с теми же
каноническими объектами. Вкладку или поддержанную Markdown-ссылку можно
скопировать как ссылку `keystone://` и открыть в текущей либо новой вкладке.
Маршруты сохраняют идентификатор объекта и, если нужно, revision/vault scope;
отсутствующий или запрещённый объект открывается как заблокированная или
недоступная поверхность, а не превращается в фиктивную запись. Полная грамматика
и поведение copy/paste описаны в [Keystone links](keystone-links.md).

## Персонализация и восстановление

Владелец может настроить Desktop shell через Settings без изменения модели
полномочий: тема, semantic colors, typography, density, layout, секции Home,
tabs, motion, shortcuts и поддержанное поведение являются типизированными
локальными настройками. Наследование областей идёт так: global → device →
workspace → surface → window. Доступны presets, undo/redo, scoped reset и
безопасный JSON transfer. Custom CSS — явный локальный слой presentation со
стабильными `data-keystone-*` hooks; remote imports, URLs, scripts и изменения
security блокируются. Safe UI mode отключает owner CSS для восстановления.
