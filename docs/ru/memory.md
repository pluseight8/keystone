# Персональная память

Personal Memory Keystone — локальный слой долговременной памяти поверх RAG. RAG индексирует материал для ограниченного поиска, а `MemoryService` хранит устойчивые `MemoryEntry` и объясняет, почему запись была сохранена и какие объекты Keystone её подтверждают.

## Записи памяти

Записи имеют тип `episodic`, `semantic`, `preference`, `relationship` или `project` и различают `fact`, `assumption` и `preference`. У каждой записи есть уверенность, важность, privacy-класс, даты и provenance-ссылки на сообщение, файл, объект сообщества, Track, Video, сессию агента или явное высказывание пользователя.

Автоматическая запись не может стать explicit или pinned по решению модели. Явные записи создаются пользователем и доступны для изменения, закрепления, пометки ошибочной и удаления. Конфликтующие сведения сохраняют обе цепочки источников; более сильная/новая запись может пометить старую как superseded, не уничтожая историю.

## Граница приватности

Память — локальное устойчивое состояние устройства. Локальная модель или доверенный персональный compute могут выполнять консолидацию по policy Keystone. Внешний provider отклоняется до передачи observations или записи candidates. `PRIVATE` и `SECRET` не попадают во внешний payload; существующий egress firewall остаётся последней границей.

Класс приватности при консолидации может только ужесточаться: данные из private-источника нельзя понизить до `PUBLIC`. Private/blocked-источники не публикуются через discovery и не превращаются в публичную память.

## Поиск

`MemoryService.search()` ранжирует ограниченный результат по смысловой близости, давности, важности и доверию к источнику. `MemoryService.context()` применяет существующий `ContextBudget`, поэтому в prompt попадают только выбранные записи, а не вся база. `MemoryContextSource` отдаёт этот результат через capability `MEMORY` существующего `ContextBuilder`.

По умолчанию используется детерминированный локальный `LocalHashEmbeddingProvider`. Host может подключить другой локальный embedder, но внешний endpoint нельзя использовать для private memory.

## Управление и забывание

UI должен позволять искать записи, открывать «Почему запомнено» и источники, редактировать, закреплять, помечать ошибкой, удалять, отключать automatic memory, забывать сообщение/диалог или очищать категорию. При забывании source автоматические записи, зависевшие только от него, удаляются; у multi-source записей ссылка убирается. Явная запись по умолчанию сохраняется с локальной пометкой «источник забыт», но policy может удалить и её.

## Устойчивость

`MemoryService` сохраняет версионированный `MemorySnapshot` через `MemoryStateStore`. Индекс и embeddings восстанавливаются локально. Неизвестная версия, плохой ID, privacy-класс или provenance приводят к fail-closed ошибке.
