# Protocol Fuzzing

`ProtocolFuzzHarness` and `HostilePeerHarness` generate synthetic empty, truncated, oversized, duplicate-key, deeply nested, huge-array, invalid-enum, replay and random frame inputs. They assert that rejection does not crash the process, allocate from an unchecked length, unlock privileged runtime, disable Safety or create capabilities.

Property-style coverage verifies:

- a domain-separated signature verifies only for the same semantic object/type;
- mutation of a signed security field invalidates verification;
- replay is idempotent or rejected;
- stale revisions cannot replace tombstones/epochs;
- arbitrary generated bytes stay within parser and resource budgets.

The real network suite includes a process-level hostile client over Hyperswarm/Noise. It sends a bounded forged SAFE envelope and an absurd declared frame length while legitimate signed peers remain alive and continue exchanging data.
