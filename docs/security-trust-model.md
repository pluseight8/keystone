# Security trust model

Keystone separates authenticity, authorization and content safety. A valid release signature authenticates the local installation; it does not make a peer trustworthy. A signed peer operation still passes local identity, membership, capability, replay, privacy and Safety checks. A model is untrusted compute, regardless of provider or whether it is local, remote or custom.

The immutable policy root authenticates minimum Safety, ToolPolicy, AI egress, protocol, crypto, sandbox and settings-authority references. Mutable preferences can select stricter behavior but cannot disable or downgrade those references. Shared/public content is eligible only after the  Safety gate; personal/private local content remains available to its owner without network content censorship.

The owner controls data and preferences. Models, agents, Skills, plugins and remote peers can propose actions, but only typed policy/confirmation boundaries can apply consequences. Official status is local evidence for diagnostics, never a network privilege.
